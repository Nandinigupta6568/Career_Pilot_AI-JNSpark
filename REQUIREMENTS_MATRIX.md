# Fetch-A-Thon 3.0 requirements matrix

Based on the hackathon brief supplied for this project. Code being present is not proof that a platform-level requirement is completed.

| Requirement from brief | Project implementation | Verification still required |
|---|---|---|
| Clear real-world problem | Career/internship planning | Show a realistic successful example |
| Multi-step planning/reasoning | ASI:One tool-calling loop and plan tool | Run a complete end-to-end request |
| Tools/APIs/external services | Four allow-listed tools; GitHub Search API | Verify network and API availability |
| At least one agent registered on Agentverse | uAgents agent configured for mailbox mode | Authenticate and verify it appears in Agentverse |
| ACP / Agent Chat Protocol | Standard `uagents_core` chat protocol and manifest | Confirm live compatibility using the current official guide |
| Discoverable and usable through ASI:One | Mailbox and manifest publication configured | Test search/discovery and invoke the deployed agent from ASI:One |
| Full primary workflow inside ASI:One conversation | Agent handler invokes career workflow and returns the answer | Demonstrate end-to-end in ASI:One without a custom frontend |
| Public GitHub repo with run/test instructions | README, tests, CI workflow, requirements, setup guide | Publish repository publicly and verify URL |
| Public ASI:One shared-chat URL | Not generated by source code | Create after a successful ASI:One conversation |
| Agentverse profile URL | Not generated by source code | Copy real profile URL after deployment |
| Demo video, 3–5 minutes | Demo outline/checklist included | Record and upload video |
| Problem, target user, outcome description | `SUBMISSION_DESCRIPTION.md` | Finalize and include real links |
| Innovation Lab category and badges | Required badges in README | Set category in Agentverse; ensure public README has badges |

## Bonus items

- Multi-agent collaboration: not implemented in this version.
- Payment Protocol: not implemented; bonus, not mandatory in the brief's eligibility list.
- ASI Interactive Cards: not implemented; recommended by the brief, not mandatory.
- Error handling/recovery: basic bounded tool loop and per-tool failure handling are implemented; live failure cases still need testing.
- Live external data: GitHub repository search is implemented; test API limits and network errors.
